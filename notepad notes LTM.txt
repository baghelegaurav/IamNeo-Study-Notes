--------------------------------------------------------------------------spark-----------------------------------------------------------

Apache Spark works on top of HDFS (Hadoop Distributed File System). Spark does not include its own storage system, meaning it must pair with an external data layer. it can also process data from cloud object storage platforms like Amazon S3, Google Cloud Storage, or Azure Data Lake storage.

spark is an alternative for Hadoop MapRaduce, it does parallel processing more effeciently-
spark performs in-memory-computation ,it completely loads the data into ram ,performs the operations and then writes the result back to file.
it can easily integrate with other environments, data lakes and data warehouses.

by default spark core perform batch processing but mainly used for real time it has spark stream.

Datalocality- it defines which data is at what worker node in spark,(location of particular data)
master node- similar like data node in hdfs
cluster manager-it assigns the resources for the process/task. it contains datalocality
driver program- for every executable task, it is generated(contqnins the requirement to complete that task eg- cpu, memory..etc)
workernode- responsible for executing task
Executor-coordinate the task within workernode- eg-akansha mam
JVM(task) - who is doing task- eg-trainer
After completion of task, result will go to DP(driver program)

in hive when we load the file, then we create schema in remote/inbuilt database, so we have 2 options to create internal and external table.
to create external table use external keyword. (create external table table_name;)

if we created internal table and later drop internal table then the metadata as well as table from the source file, both will be deleted.
but in external table only the metadata will be deleted from from remote/inbuilt database.

for making external table , manually load the file from local path to hdfs and then make external table through hive

default path of file after loading - user/hive/warehouse

Disadvantage of Derby(Inbuilt database)-
for every worker-node ,you have a separate Derby ,unlike Remote Database which is commom for all workernode,so in Derby if any worker-node goes offline then the metadata or table scheme also gets lost but in Remote it doesn't happen.

        LEFT JOIN topups t
            ON e.hub_id = t.hub_id

Public IP address- Public/Internet Communication

VPC Network: A global, virtual boundary that provides private connectivity for your cloud resources across the entire world.
Subnet: A regional IP address range within a VPC used to organize, isolate, and host your virtual machines and services.
Region-Wise Subnet: The structural design in GCP where every subnet belongs strictly to one geographic region, but multiple subnets across different regions can talk to each other globally inside the same VPC.
An IPv4 address consists of 32 bits total, divided into a Network ID (identifying the network) and a Host ID (identifying the specific device), written in Classless Inter-Domain Routing (CIDR) notation (e.g., /24).
🛠️ How Bits are Divided (The /24 Example)
In a standard 10.0.0.0/24 block:
Network ID: The first 24 bits define the network prefix (10.0.0.X). These bits are locked and cannot change.
Host ID: The remaining 8 bits (32 total - 24 network) are left to assign up to 256 unique addresses for your virtual machines.
🛑 Reserved IP Addresses in GCP
In every GCP subnet, Google automatically reserves the first two and the last two IP addresses in the range for network infrastructure:
.0 (First IP): Network Address (identifies the subnet itself).
.1 (Second IP): Default Gateway (used by VMs to route traffic out of the subnet).
.254 (Second to last IP): Reserved by Google for future infrastructure usage.
.255 (Last IP): Broadcast Address (reserved for network broadcasting functionality)

EXTERNAL vs Native table in BigQuery-

Native Tables - In a Native table, the actual data is physically moved from your external source and stored directly inside BigQuery's internal storage system. While copying massive datasets into BigQuery takes time upfront and incurs monthly storage fees, it makes your queries incredibly fast. This speed happens because the data is pre-converted into BigQuery’s highly optimized, compressed format on local disks, allowing the system to scan and process information instantly without any data traveling across a network during a query.

External Tables - In an External table, the actual data never moves and stays completely inside its original source, such as Google Cloud Storage (GCS).
This setup saves you from BigQuery storage fees and means you can query the data immediately without waiting for a long upload process. However, queries are much slower because BigQuery has to fetch the raw files over the network and convert them on the fly every single time you run a search, and you lose out on advanced performance features like clustering and time travel.

Apache airflow - is the ochestration tool for doing automation on schedule basis

Apache Airflow is a Python-based open-source platform that helps organizations schedule, automate, monitor, and manage complex workflows and data pipelines using DAGs.
 
DAG:

Directed Acyclic graphs-A DAG (Directed Acyclic Graph) is a workflow that defines tasks and the order in which they should run, without creating any loops. Apache Airflow uses DAGs to automate and manage workflows.

It understands only python files
 
Scheduler:

The Airflow Scheduler is a component that continuously monitors DAGs, checks their schedules and dependencies, and triggers tasks to run at the appropriate time. It only decides-

	When to start

	Which step is next

	Whether a step can run

The component in Airflow that decides when a workflow or task should start.
 
Executer:

The Executor is the component in Airflow that decides where and how tasks are actually run.

Executor decides WHERE and HOW the task runs.
 
Worker:

A Worker is the component that actually performs the task.

A Worker in Apache Airflow is a process or machine that executes the actual tasks assigned by the Executor. It performs the work defined in the DAG and reports the task status back to Airflow.

Windowing - 

In stream processing, you are dealing with unbounded data—an infinite, continuous river of incoming data points (like user clicks or sensor readings).

Because a stream never stops, you cannot calculate a standard metric like a global average or sum. You have to slice the infinite river into finite, manageable blocks of time. This slicing mechanism is called Windowing.

1. Fixed Windows (Tumbling Windows): Time is divided into uniform, non-overlapping, contiguous chunks (e.g., exactly every 5 minutes).
		Example- You run a cloud monitoring dashboard and need to display a line chart of API requests per minute. You configure a 1-minute Fixed 		Window. Every 60 seconds, the pipeline totals up the requests received in that block and updates the graph.

2. Sliding Windows (Hopping Windows): Time windows that have a fixed duration but overlap with each other. They are defined by two metrics: the window size (length) and the slide (how often a new window opens).
		If your window size is 10 minutes and your slide is 1 minute, a new 10-minute window opens every single minute.

3. Session Windows: Dynamic windows that do not have a fixed time length. Instead, they are defined by a gap of inactivity (e.g., 30 minutes of silence).
			The window opens when a user performs an action. It stays open as long as the user keeps generating events. If the user stops 				interacting for longer than your specified "gap duration", the window snaps shut and outputs the final result.
----------------------------------------------------------------------
1. Watermark: An internal system clock that estimates how far data processing has progressed.Why: Tells the system when it can probably assume all data for a specific timeframe has arrived, despite network delays.
	Example: for a window of 2pm-3pm, watermark could be 3:15pm, so we can assure that till this time all the inputs have arrived.

2. Triggers: The alarm or rule that tells a time window exactly when to output its current results.Why: Allows you to see real-time, early updates on a dashboard instead of waiting hours for a window to officially close.
	Example: A trigger fires every 10 seconds to update a live website graph with current sales, even though the overall hour isn't finished.

3. Allowed Lateness: A grace period that keeps a window's memory alive after the watermark has passed.Why: Prevents the system from permanently dropping valid data that arrived late due to a device losing internet connection.
	Example: You set a 1-hour grace period. A phone that was offline since 2:30 PM reconnects at 3:45 PM; the system accepts its data and updates the 	2:00 PM ledger.If you are putting these notes into practice.

Hotspotting -

Hotspotting is a severe performance bottleneck that happens in distributed databases (like Google Cloud Spanner or Cloud Bigtable). It occurs when all incoming write or read operations hit a single database machine (node), while all other machines in the cluster sit completely idle and do nothing.

If your primary key design uses monotonically increasing values—meaning every new row gets a key that is strictly higher than the last one (such as a sequential Order_ID like 1001, 1002, 1003, or a real-time timestamp)—every single new write will always land at the very end of the sorted list.Because it lands at the end of the list, it lands on the exact same server. 

As a result, that one server gets overwhelmed and crashes, while the other servers you are paying for do zero work.

Solution-

Use a UUIDv4: Instead of sequential numbers, use a random string (e.g., f81d4fae-7dec-11d0...). Two orders created at the exact same millisecond will get completely different random starting letters, scattering them across all 20 servers instantly.

Idempotent - 

Idempotency means an action can be repeated multiple times, but the final outcome remains exactly the same as if it ran only once.
In data engineering and distributed systems, an idempotent pipeline is a safety net. If a system crashes halfway through a task and restarts, it will not corrupt your data with duplicates.

The Solution: 

1. The Overwrite Strategy (INSERT OVERWRITE)Instead of appending new rows directly to a table, the system explicitly wipes out the target partition or destination for that specific timeframe before writing fresh data.

2. The Merge/Upsert Strategy (MERGE INTO)The system evaluates a unique identifier like a primary key (transaction_id or user_id) to check if a record already exists in the target table before committing a write.

For streaming there are 2 methods-
-----------
Option 1: In-Flight Update (Recommended for Streaming) -
	Dataflow allows you to replace a running streaming pipeline with a new version. The new pipeline takes over the job state, buffered data, and  windows from the old pipeline with zero downtime and no data loss.
-----------
Option 2: Drain & Re-launch (No data loss)-

Phase 1: Closing the Intake ValveDataflow immediately stops pulling new messages from your source (like a Pub/Sub topic or Kafka). The new incoming data simply waits safely in Pub/Sub. No data is lost.
Phase 2: Clearing the Backlog. The Dataflow workers keep running to process every single message that was already inside the pipeline when you hit drain. It completes all current window calculations and time-stamped groupings.
Phase 3: Clean ShutdownOnce the pipeline is completely empty and all processed data is safely saved into your database (like BigQuery), Dataflow automatically shuts down and stops charging you money.
The Relaunch:Now that the old job is cleanly stopped, you deploy your brand new code as a completely fresh Dataflow job. It starts pulling the waiting data from Pub/Sub from exactly where the old job left off.

IMP-While the old pipeline is draining and shutting down, your upstream source (like Google Cloud Pub/Sub or Kafka) keeps collecting new data from your users or applications.

Private Google Access (PGA) - 

It is a VPC subnet setting allowing virtual machines with only internal IP addresses to securely access Google API endpoints, such as Cloud Storage and BigQuery, without requiring a public, internet-facing IP address.

By default, if a Virtual Machine (VM) in GCP does not have a public (external) IP address, it is completely isolated. It cannot talk to the internet, and it cannot talk to Google services like Cloud Storage, BigQuery, or Secret Manager. This is because Google APIs are technically hosted on public IP addresses.

Private Google Access (PGA) is a single toggle switch on a VPC subnet. When turned on, it allows VMs that only have internal (private) IPs to reach Google APIs and services. The traffic never leaves Google's private fiber-optic network and never touches the public internet.
